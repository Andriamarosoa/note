# NOTE — Onset fifth learned FP-discrimination head, 69D vs 70D vs 74D, native PCM256

**Experimental branch:** `codex/note-fp-temporal-discriminator-74d-256`.
**Pre-registered hypothesis:** [H_FP_PARENT_TIMELINE_01, GitHub issue #142](https://github.com/Andriamarosoa/note/issues/142). Overarching failure-to-confirm audit rule: [issue #140](https://github.com/Andriamarosoa/note/issues/140).

## Why this experiment and NOT a fixed harmonic veto

Original true native256 S613: TP8099 FP4600 FN3168, F1=67.5874155% on 80 GuitarSet WAV and 306536 decision hops.

Third-head ErrorPrediction MLP69 after no-feedback fix: TP8054 FP4411 FN3213, F1=67.8745997%. Best four-head Onset + independent FNRecovery MLP69: TP8160 FP4605 FN3107, F1 **67.9094541%** ([#39759373185](https://github.com/Andriamarosoa/note/actions/runs/39759373185)). Recovery produces 106 additional TP but 194 additional FP. The all-negative FNRecovery retraining was REFUTED as a solution because it yielded TP8100 FP4500 FN3167, F1 67.8761%. This result was honestly retained ([#39765038340](https://github.com/Andriamarosoa/note/actions/runs/39765038340)).

Signed [residual FP audit #39772165153](https://github.com/Andriamarosoa/note/actions/runs/39772165153) verified that **4411 FP are already present before FNRecovery**, 3548 in accompaniment and 863 in solo. In the lower register E2–B2, 624 of 1226 proposals are false; mid-register C3–B3 has 2145 FP. **Within a strictly previous 80ms harmonic parent native NoteOn** (+12/+19/+24/+28 semitones), there are 782 FP but ALSO 678 legitimate TP. Blindly vetoing them causes an **event-only counterfactual F1 66.2356%**, far worse than our best native256. Another 3629 FP do not belong to this parent group.

## Falsifiable hypothesis and three independent neural controls

H_FP_PARENT_TIMELINE_01 proposes that some FP/TP ambiguity may be resolvable by learning the chronology of prior acoustic note attacks, instead of a hand-written harmonic veto.

To avoid confusing effects of existing neural confidence and the new harmonic timing, **all three neural ablations** are independently fitted using exactly the same TRAIN events, fold seeds, ML architecture and CAL composition:

| Head | Input vector available BEFORE current Onset decision | What it isolates |
|---|---|---|
| **control69** | Original 69D causal acoustic+S701+Onset predecision-state features | Replicate same learning capacity on existing features |
| **control70** | control69 + frozen MLP69's current **P(correct)** | Additional confidence only; temporal ablation |
| **temporal74** | control69 + 4 normalized ages since LAST NATIVE MAIN attack at parent intervals −12/−19/−24/−28 semitones + P(correct) | The **incremental** information from causal harmonic chronology |

All three are real `StandardScaler + MLPClassifier(64,32)` (15 new networks: 5 composition folds × 3 variants). Their weights, input sizes, heldout TRAIN/CAL/OUTER compositions, exact calibration cuts and SHA256 are saved as immutable artifacts. None are 1024-trained S708 checkpoints.

**Important causal ordering:** `OnsetHeadStack` first computes main acoustic S613, rescue S701, error MLP69 and FNRecovery neural predictions, then all three new FP predictors **BEFORE selection** at each fresh 256-sample boundary. The harmonic age state contains **ONLY native Main NoteOn at previous hops**, is read-only before current prediction, and updates ONLY AFTER the entire current Onset selection. No ground truth, future samples, external Pitch/K/Offset or MIDI output is referenced.

All new FP heads may only **reject a NoteOn already accepted by the ErrorPrediction head**. They cannot modify S613's posterior, armed state, release, refractory, or any other head. Existing FNRecovery extra NoteOns are preserved unchanged in each variant. Their final simulated output is `fp_discriminator_unified[variant]`, Onset-only experimental, not production MIDI.

## TRAIN/CAL/OUTER protocol and objective

- Evidence source: `fp_signals74.jsonl` generated by earlier **true 80-WAV PCM256 original audio replay**. TP/FP labels are read ONLY after that signed replay, never by any runtime head. A training vector is guaranteed to contain 74 pre-decision numeric inputs and its TP/FP label stored separately.
- Each of the five folds uses **3 TRAIN compositions**, **1 CAL composition** for threshold only, **1 OUTER composition** held untouched before cut freeze. Each composition has 16 GuitarSet tracks. All 3 variants use identical positive/negative training events and identical random seed per fold.
- The CAL threshold is chosen on a **clearly labelled fixed-event F1 proxy** which approximates vetoing already recognized TP/FP while preserving FNRecovery events. It is not presented as real replay F1, because reassignment of event matching could alter results.
- Only after three CAL cuts frozen is OUTER processed, and full **original audio 80 WAV / 306536 strictly causal fresh PCM256 hops** is replayed with all previous four heads and all 3 FP ablation heads computing outputs EVERY 256. After each entire track, GT is read, and true TP/FP/FN/F1 re-matched.
- The four earlier heads must reproduce **TP8160 FP4605 FN3107** exactly; any difference fails CI. Compare 69D,70D,74D head outputs on identical hops. Report per-track/per-composition regressions, and REAL total FP/F1.
- **Pre-registered decision rule** (before inspecting OUTER): temporal74 must have **strictly fewer REAL FP than both control69 and control70**, REAL F1 **≥67.9094541%** versus best previous four-head, and REAL F1 **≥control70**. If not, **hypothesis REFUTED_OR_INCOMPLETE**; no promotion; recompute error categories before proposing further changes. No threshold tuning on OUTER or replacement benchmark.

## Scientific caveats

Old S613/S701 teachers had previously seen some FIT80 samples during their earlier training (20/80,48/80 tracks). New ablation's OUTER labels are untouched in its own fit, **but this is NOT external generalization of the entire historic pipeline**. The 256-hop cadence is about **5.805ms at 44.1kHz**, not measured end-to-end input/CPU/MIDI latency; 2048/4096/8192 window inputs are historical (not future). No wait/confirmation-delay/hold introduced. None of the other five feature architectures (Exact-K, Active-K, Frame Pitch, Offset, Full Note) or public MIDI code is edited.

**At creation:** hypothesis pre-registered, model code and tests staged; there is **no new scientific performance claim until the GitHub full-WAV workflow ends**.
